# Teaching Notes: Unit 3: Transcriber-Focused Lessons

These notes support Lessons 20 to 24. Unit 3 is a production workflow, so teach it as one connected sequence and not as five separate tools.

## Lesson 20: Importing and Working with NIMAS Files

**Read the lesson:** [Importing and Working with NIMAS Files](../lessons/20-nimas-production-files.md). **Suggested time:** 150 minutes.

### Demonstration idea

Open a sample NIMAS textbook chapter and, before making any changes, use the Book Tree to answer three questions out loud: How many major sections does this lesson have? Where are the practice problems relative to the main instructional text? Is there a glossary or notes section at the chapter's end? Only after mapping the chapter's shape this way should learners begin detailed style review — this mirrors the "read before you fix" principle from [Lesson 2](../lessons/02-opening-word-documents.md), applied to a file type that offers a purpose-built tool (the Book Tree) for doing exactly that reading efficiently.

### Tips and pitfalls

**Tip:** New transcribers sometimes treat a NIMAS file's automatic formatting as fully trustworthy simply because it's structured markup rather than a "messy" Word document. Correct that assumption early: NIMAS gives you a much better *starting point* than an unstructured file, not a finished product. The review habits from [Lesson 2](../lessons/02-opening-word-documents.md) still apply — they're just applied to a smaller set of remaining issues.

A common pitfall: skipping the Publisher's Production Notes because they seem like optional reading. They frequently contain exactly the kind of context (how a particular recurring feature was intended to be handled) that prevents a transcriber from re-deriving a formatting decision from scratch, or getting it wrong.

### Check for understanding

- Navigates with the Book Tree.
- Decides on each production note and can say why.
- Finds and corrects a missing heading.

### Extension activity

Provide learners with a short sample NIMAS chapter. Have them use the Book Tree to produce a written outline of its structure before opening the detailed Print View, then review the chapter for at least one instance of print-only formatting (such as bold carried over on a heading) that needs to be removed despite the heading itself being correctly identified.

## Lesson 21: Running Heads and Page Numbering

**Read the lesson:** [Running Heads and Page Numbering](../lessons/21-running-heads-and-page-numbers.md). **Suggested time:** 150 minutes.

### Demonstration idea

Set up a short practice document end to end:

1. Add a **Running Head** reading the (short) title of the practice document.
2. Type a two-page print excerpt where the print page break falls mid-way through a braille page — mark the print page number using **Styles > Miscellaneous > Page**, and confirm the page-change indicator appears correctly.
3. Insert a title page and a one-paragraph transcriber's note *before* the main content, and set their braille page number type to **T-page** via the Page Number Dialog; confirm the main content itself begins as **Normal**, braille page 1.
4. Open the **Page Change List** and confirm every manual change made during the exercise is accounted for and intentional.

### Tips and pitfalls

**Tip:** Page numbering is one of the few areas where getting the *concept* right (print vs. braille pagination as two independent tracks) matters more than memorizing every dialog tab. Spend real time up front making sure learners can explain, in their own words, why a print page 5 might correspond to braille pages "5," "b5," and "c5" — once that clicks, the individual dialog tabs are mostly just "where do I make this specific change," which is easy to look up.

A frequent pitfall: setting a running head without checking it against the longest print page number the document will actually use, only to find it doesn't fit once a three-digit page number appears later in the book. Check the extremes, not just the first page, before finalizing.

Another common mistake: forgetting to switch the page number type back to **Normal** at the actual start of content after using T-pages or P-pages for front matter — leaving the whole document numbered as transcriber pages.

### Check for understanding

- Distinguishes print from braille page numbers.
- Checks a running head against the longest page number.
- Reviews the Page Change List before finishing.

### Extension activity

Have learners build a short practice volume containing: a T-page title page, a T-page transcriber's note, a Normal-numbered main body spanning at least two print pages (with at least one print page runover), and a running head. Ask them to review the finished document's Page Change List and write a one-sentence justification for each entry.
