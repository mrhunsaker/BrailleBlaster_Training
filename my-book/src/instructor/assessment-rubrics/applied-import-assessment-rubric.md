# Applied Import and Conversion Assessment — Scoring Rubric

**Total: 100 points**  
Score evidence and process, not merely whether the final file opens.

| Criterion | Points | Full-credit evidence |
|---|---:|---|
| Source inspection and structural analysis | 15 | Correctly identifies semantic structure, content dependencies, and source defects across formats |
| Import-route selection and rationale | 10 | Selects a defensible route, records tool/version details, and acknowledges limitations |
| Conversion/import execution and traceability | 10 | Preserves originals, uses reproducible steps, and records warnings and transformations |
| Content integrity | 20 | Preserves wording, sequence, values, symbols, units, and all required elements |
| Structural fidelity and remediation | 15 | Correctly restores headings, lists, tables, equations, figure information, and navigation |
| BrailleBlaster review and translation verification | 10 | Checks structure and translated output in context using applicable code/settings/specification |
| Defect log and evidence quality | 5 | Findings are located, classified, prioritized, corrected, and verified |
| Final QA and production recommendation | 10 | Release recommendation is evidence-based, limitations are explicit, and unresolved issues are disclosed |
| Professional file handling and handoff | 5 | Clear filenames, preserved originals, organized deliverables, complete manifest |
| **Total** | **100** | |

## Performance bands

| Score | Rating | Interpretation |
|---|---|---|
| 90–100 | Production-ready performance on this exercise | Accurate, traceable work with effective verification and defensible decisions |
| 80–89 | Proficient | Minor omissions that do not compromise content integrity |
| 70–79 | Developing | Workflow is partly sound, but verification or remediation is inconsistent |
| 60–69 | Below standard | Significant gaps in structural analysis, traceability, or QA |
| 0–59 | Not yet competent | Evidence is insufficient or critical content defects remain |

## Critical-defect override

A numerical score does not override a critical defect. Mark the assessment **Not Yet Accepted** until corrected if any of the following remains:

- A source paragraph, question, table row, or required figure description is omitted.
- A numerical value, mathematical symbol, or unit is changed without an authorized source correction.
- Reading order or heading/list hierarchy materially changes meaning.
- A conversion defect is mistaken for source content and silently accepted.
- A student reports successful verification for a feature that was not actually tested.
- An original source is overwritten and no recoverable baseline exists.

After remediation, record the revised score and the defect-closure evidence. A critical-defect gate is a release condition, not an extra point deduction.

## Scoring consistency notes

- Accept alternative workflows when they are supported by the installed software and the learner documents the rationale.
- Do not penalize a learner for a documented application limitation; assess the proposed mitigation and disclosure.
- Do not require identical braille output when code, settings, or production specifications legitimately differ.
- Award content-integrity points only when evidence is compared with the authoritative source.
- Treat an attractive visual layout as insufficient evidence of semantic structure.
- If a scenario cannot be run in the available environment, award analysis credit only for clearly identified limits and a reproducible test plan; do not award execution or verification credit.
