# Student Competency Portfolio Guide

## Purpose

The portfolio is a curated record of demonstrated production judgment. It connects lesson practice, applied assignments, unit checkpoints, the practical assessment, and the capstone. It is not a folder of every file you have created: retain representative evidence that shows the task, your decisions, verification, and the final result.

## Build the portfolio as you work

1. Create a clearly named folder for the course and a subfolder for each unit.
2. Preserve original source files unchanged. Store working copies separately.
3. For each substantial task, complete an [evidence log](competency-evidence-log.md).
4. Keep the source version, BrailleBlaster project version, and exported deliverable identifiable.
5. Select evidence that demonstrates a competency, not merely that a task was attempted.
6. Request instructor review and record the decision on the [skills sign-off sheet](competency-skills-signoff.md).
7. For major assignments and the capstone, complete a [project review record](project-review-record.md).
8. Use the [course-completion checklist](course-completion-checklist.md) to identify gaps before final review.

## What counts as evidence

Examples include a source-to-structure map, import comparison, documented repair, decision log, Braille View verification notes, ASCII excerpt, pagination plan, table or figure rationale, proofreading record, test-emboss notes, corrected project, and production handoff manifest.

A screenshot may supplement evidence, but should not be the only proof of a structural or translation decision. Describe what was checked and what result was observed. Where practical, include a short text excerpt or reproducible check.

## Evidence quality standard

Every portfolio item should answer:

- **Task:** What requirement or production problem did you address?
- **Context:** Which source and version did you use?
- **Decision:** What did you choose, and why?
- **Action:** What did you change or leave unchanged?
- **Verification:** How did you compare the result with the authoritative source and expected output?
- **Outcome:** What passed, what remains unresolved, and who reviewed it?
- **Reflection:** What would you repeat or change on the next job?

## File naming and version control

Use stable, descriptive names, for example `U2-A06-import-comparison-v2`. Include dates in ISO format when dates are needed (`YYYY-MM-DD`). Do not overwrite the original source. Distinguish drafts, reviewed versions, and final deliverables. If using Git, commit meaningful milestones and do not place confidential production material in a public repository.

## Privacy and professional handling

Use the fictional course specimens for portfolio examples. Do not include student records, client names, protected educational records, unpublished copyrighted source material, personal contact information, credentials, or other confidential data in a portfolio shared with classmates or stored in a public repository. Follow your organization's retention, access, and deletion policies for real production work.

## Final review

A complete portfolio includes representative evidence across all four units, the required assignment and checkpoint results, the practical assessment outcome, capstone review and handoff, and instructor sign-off. Use the completion checklist to record exceptions; do not mark a requirement complete merely because a file exists.
